## 1. 一句话

**从 TikTok、X、Product Hunt、Reddit 四个地方，找出"一个新格式正在被模仿"的名字，把它变成一条可执行的关键词，当天交到人手里。**

交付物是**关键词**，不是名字；名字只是证据。

## 2. 不做什么

- 不做站点生成、模板、支付、部署。radar 只到"这条词能不能做、怎么做"为止。
- 不做老词。慢线、autocomplete 收词、稳定通用词，全部不在范围内。
- 不做 push / 邮件 / 定时通知。每天一份 Markdown。
- 不做 review 模块（理由见 7.6）。
- 不碰国内；只做 en-US。

## 3. 第一原则：从群众出发

一条词成立，要同时满足三个"普通"：

- **人要多**——不是十几个开发者，是几万个普通人；
- **事要具体**——"把猫 P 进橙光酒店"可以，"做个 AI 工具"不行；
- **要是现在**——4 天窗口，过了就是废词。

自检一句话：**能不能给我妈讲明白她在搜什么、为什么要搜。** 讲不明白的，不进报告。

## 4. 现状 → 目标

| | 现在（2026-10-30 的库） | 目标 |
|---|---|---|
| 源 | 12 路，全在供给层 | 4 路（X、TikTok、PH、Reddit） |
| 产出 | 每天 20 个名字，`keywords` 表 0 行 | 每天 0–10 条关键词，每条九字段 |
| 判据 | 圈内声望（★300、♥、PH 票） | 用法在扩散 + SERP 窗口还开着 |
| 报告 | 每天覆盖同一个 `report.md` | `reports/YYYY-MM-DD.md`，按源分节 |
| 存储 | `leads`，`source_id`/`url` 全空 | `deliveries` 表，每条可溯源 |
| 成本 | $0.33–0.47/天 | 约 $0.2–0.3/天（SERP 实测 $0.002/条） |
| 结果 | 15 天 416 词，0 条可用 | 每天至少 1 条"敢给朋友看"的 |

## 6. 阶段二：每个源怎么处理

### 6.1 一个算法，四个适配器

抓取层每个源都不一样（TikTok 调 Apify、PH 调 GraphQL、X/Reddit 调 AIsa），但**只到"抽出候选"为止**；候选之后的闸门、长尾、SERP、九字段，四个源共用同一套代码。加第五个源，只写一个 `fetch → 候选` 的函数，不碰后面。

**候选结构**（每个源都抽出这个）：

```
{term, source, first_seen, speed, context, url}
```

- `context` 是原话/语境：推文正文、tagline、Reddit 帖子原话。**它是需求句的原料，不能丢。**
- `speed` 只有 TikTok 有：`{usage_change, rank, rank_change, chart}`，其余为 `null`。
- **同词多源**：归**首次发现**的那个源，其余写一行"也见于 X"。
- **一条候选只留一天**：今天没进交付的，明天重新从源里来，不累积。

**处理顺序**（便宜的在前面）：

```
去重 / 停用词（免费）
  → 闸门一：在加速（TikTok 看 usage_change；其余见 Q1）
  → 联想取长尾（免费）→ 判类型
  → 闸门二：SERP（$0.002/条，只查准备交付的）
  → 写九字段
```

### 6.2 X

- 抓：7 个账号最近 20 条（AIsa，约 $0.012/天）。
- 抽：`terms.names()` 抽名字；**保留发帖人和原话**。
- 判：这条是不是"一个新东西的名字"，而不是模型名或公司名。
- 出：候选 `{term, context=推文正文, url=推文链接}`。

### 6.3 TikTok

- 抓：每天一次 US `popular` + `viral` 各 25 条（Apify，$0.003/行 → **$0.15/天**）。
- 存：`state/tiktok/<date>.json.gz`，字段 `usage_change, rank, rank_change, title, artist, sound_id, tiktok_url`。
- 抽：名字（曲名/艺人，见 Q2）。
- 排：`usage_change` 降序；闸门一就是它。
- 出：候选带 `speed`，这是唯一"能证明现在"的源。

### 6.4 Product Hunt

- 抓：AI topic 下的发布（GraphQL，免费）。
- **改**：不再只用 `name`。进详情页读 `tagline` / `description` / `How it works` / 分类 / 定价，抽出"**谁 + 要什么 + 怎么给**"。
- 出：候选的 `context` 是那句需求描述；**品牌名只当附件**，不当关键词。

### 6.5 Reddit

- 抓：`is there an AI tool that…` 一类求助帖（AIsa，约 $0.002/条）。
- 抽：原话 + subreddit + 链接；LLM 把原话改写成 2–6 个"别人会怎么搜"。
- **不查搜索量**（16.7 定的）。
- 出：候选 `{term=改写后的搜索说法, context=原话, url=帖子}`。

### 6.6 人工丢词

群里/博主/自己刷到的词，手动丢进来，走同一条处理链。两篇复盘的词全来自这一步。入口形态见 Q7。

## 7. 阶段三：结果怎么交付

### 7.1 一条交付是什么

**一条 = 一个格式 + 它下面的一组长尾关键词。**

裸词（`hotel lobby`）不单独交付，它只是把手。用户真正搜的是 `hotel lobby ai video free` 这种——长尾是市场长出来的，不是我们拼的。

### 7.2 两类，必须标

| 类型 | 长尾长什么样 | 卖什么 | 例 |
|---|---|---|---|
| **工具型** | generator / maker / editor / free / template / how to | 付费生成、订阅、按次 | `ghibli photo generator` |
| **信息型** | lyrics / meaning / net worth / who is | 流量 + 广告，或导流到工具 | `bulin 47 lyrics` |

不标类型的建议等于没写。`bulin 47` 的联想里一个"我想做"都没有，却是 72 小时 $5,480 那条——没有信息型，它会被自己的规格淘汰。

### 7.3 九字段（缺一不交付）

| # | 字段 | 写什么 |
|---|---|---|
| 1 | **关键词** | 一条真实长尾 |
| 2 | **类型** | 工具型 / 信息型 |
| 3 | **用法** | 谁拿它干什么，一句话 |
| 4 | **为什么抓** | 今天的数字，例：TikTok `Dame Hombro` 日增 16,199 条 |
| 5 | **来源** | 平台 + 链接/ID + 抓取时间 + 原话片段 |
| 6 | **证据** | 长尾或 SERP 首页事实 |
| 7 | **做什么页** | 一屏能做完的页面 |
| 8 | **卖给谁 / 怎么变现** | 具体人群 + 收费方式 |
| 9 | **凭什么现在做** | 从 SERP 首页构成来 |

**自己都不好意思介绍的一条，不要放进报告。** 类型标错，7–9 全错。

### 7.4 两道闸门

| 闸门 | 怎么量 | 成本 |
|---|---|---|
| **在加速** | TikTok `usage_change`、排名变化 | 已有 |
| **窗口还开着** | SERP 首页 10 条：几条在服务这个需求、什么站型 | $0.002/条（2026-11-02 实测） |

**联想不是闸门**，它只干两件事：收长尾（免费）、判类型。2026-11-02 回测：联想**恒返回 10 条**，`bulin 47`（刚起量）和 `ghibli photo`（早爆）都是 9 条尾巴，没有区分度。

联想按 IP 地区返回，**必须带 `gl=us&hl=en`**；否则出口 IP 在港台，会拉回 `hotel lobby 中文歌詞` 这类中文长尾，把中文需求当成美国需求。

**用法偏移也不是闸门**：45 条真实视频测 3 个词，3/3 全判 format，包括预设对照。凡扩散必偏移，是必要条件不是充分条件。

### 7.5 报告

- 一天一份：`reports/YYYY-MM-DD.md`。当天重跑可覆盖，**昨天的不覆盖**。
- **按首次发现源分节**：X / TikTok / Product Hunt / Reddit。
- **某源 0 条也写**："今日 0 条（候选 N 条，没有一条过闸）"。分不清"没信号"和"源挂了"是最贵的错误。
- 开头三行：今天几条、来自哪几个源、最值得看的是哪条。
- 两栏：`今日新交付`、`以前交付过（近 7 天，不复测）`。近 7 天交付过的词**不再占今天的名额**（丢弃原因 `already`），这一栏只是把它们列出来；review 已砍，不判断还涨不涨。
- 正文 ≤10 条，超出的进"备查"；每源最多 3 条。
- 5 次 SERP 按源轮转（X → TikTok → PH → Reddit 各一条，再第二轮），**不按速度全给 TikTok**。

### 7.6 存储、备份、不做 review

- **SQLite 是唯一事实源**：每条交付、每次抓取、每个来源都落库。
- 每条至少存：平台、原文链接/ID、抓取时间、原话片段、`run_id`。
- 每天的 MD 可覆盖；历史在库里。
- **不进 git**；数据库每天拷一份 `state/backup/YYYY-MM-DD.db`，留 30 天。
- **不做 review 模块**：数据存全了，回看就是一句 SQL。报告里只留一行"近 7 天交付 N 条"（不复测，不判断还涨不涨）。

### 7.7 成本

| 项 | 每天 |
|---|---|
| TikTok 快照 50 行 | $0.15 |
| X 7 账号 | $0.02 |
| Reddit 12 个句式 + 分类 | $0.03 |
| SERP 5 条 | $0.01 |
| LLM 写九字段 ×5 | $0.015 |
| **合计** | **约 $0.22，按 $0.3 预算** |

不合格的词在闸门就掉了，不花钱。

## 10. 验收标准（做完的定义）

改完之后，下面每一条都能当场验证：

1. `python -m radar daily` 一条命令跑完，产出 `reports/YYYY-MM-DD.md`。
2. 报告里四路各有一节（另有人工丢词一节）；某源没结果时写"0 条"，不省略。

4. 每条都能点到原始链接/ID 和抓取时间（人工丢词一行例外：来源就是 `seeds.txt` 里那一行，没有外链）。
5. `deliveries` 表能按天查历史（`python -m radar deliveries --days 7`）。
6. 单日成本 ≤ $1。
7. 日志里不再出现 sitemaps / HF / newsite / GSC / HN / breakout / revenue / official / slow 的调用。

## 附录 C：更正记录（被推翻的判断）

1. "热度可当新鲜度" → 热度只证明圈内声望。
2. "名字是产出" → 名字是线索，关键词才是产出。
3. "搜索量是判据" → 搜索量量存量，新词要增量；它只能反向诊断源。
4. "GitHub breakout 是唯一验证过的路" → 它只是唯一进过复盘的路，仍是供给层。
5. "数据源越多越好" → 9 个泛泛地抓，不如 4 个抓透。
6. "TikTok 是格式源" → 它是名字源 + 速度源；格式藏在视频文案里。
