# 孟健路线：品类组合词工厂

> 来源：`gitignore/mengjian/` 三篇文章
> 结论：这是**慢线**（周/月级窗口）的「组合型新词」产线，不是天级「新名字」雷达。

## 一、三篇 = 一条路线的三个版本

| 版本 | 文章 | 形态 | 数据源 | 成本 |
|---|---|---|---|---|
| v0 手工 SOP | 《Google「新词」找到 0-1 机会》 | 人肉：词根 → 下拉 → Trends | Google 免费 | $0 |
| v1 全自动 | 《OpenClaw 11 步全自动挖掘系统》 | 11 步 pipeline + cron + Telegram | pytrends / DataForSEO / HN / GitHub / Tavily | $2–3/次，月 $60–90 |
| v2 社区复刻 | 《让 OpenClaw 每天帮你找赚钱机会》 | 免费化 + 变现判断 | Google Autocomplete / Brave / Tavily / X | $0 |

v2 不是新方法，是 v1 的**降本 + 补维**：去 DataForSEO，补 CPC、SERP 付费产品、竞品质量、X 点赞、连续上榜、种子词自动扩展。

## 二、四栏拆解

### 信号源
- 搜索侧：Google Autocomplete（词前/词后/词中空格）、Google Trends 7 天 Rising、大站 sitemap（如 CrazyGames）
- 社区侧：HN Algolia（免费）、GitHub Search、Tavily（代抓 Reddit / Product Hunt）、X/Twitter
- 数据侧：DataForSEO Keywords（量/KD/CPC）、DataForSEO SERP、Brave Search

### 发现机制
- 新词线：词根 × 空格变体 → 下拉候选 → Trends 对比基准词 `gpts`
- 老词线：127 个根 × 每根 20 个相关词 ≈ 2540 个候选
- 社区线：用候选词反查 HN/GitHub/Reddit 讨论
- **关键设计**：社区词不直接进 shortlist，必须回流 Trends 走同一套验证

### 判断链

| 层级 | 规则 | 阈值 |
|---|---|---|
| 趋势（新词） | `avg_ratio` / `last_ratio` / `slope`，对比 `gpts` | `last_ratio>6 且 slope>0` 强上升；`avg_ratio>3 且 last>avg` 稳步涨；`slope<0 且 last<avg` 衰退 |
| 老词 | 量 + 难度 + 意图 | 月搜 >1000、KD <30、非品牌、非导航；按 `volume/KD` 排序 |
| 社区 | 仅作证据 | HN 提及数 / 评论深度 / 情绪；GitHub repo 名；Tavily 痛点 |
| SERP | 前 10 大站 vs niche 站 | niche ≥7 绿；5–6 黄；≤4 红（维护 30+ 大站名单） |
| 分级 | 至少两个维度有证据 | ✅ 值得继续 / ⚠️ 可观察 / ❌ 不做 |

### 工程形态
- 11 个 Python 脚本 + 1 主编排 + `data/pipeline_results/` + `reports/`
- cron 每天跑，结果推 Telegram、同步 Notion
- v2 免费降级栈：Autocomplete + Brave 替代 DataForSEO，Tavily 替代 SERP API

## 三、关键认知：组合型 vs 命名型

| | 组合型新词 | 命名型新词 |
|---|---|---|
| 例子 | `ai tattoo generator`、`kling ai motion poster`、`ai humanizer` | `Strata`、`Seedance`、`Nano Banana` |
| 出生方式 | 旧词根 + 新修饰 | 全新专名 |
| 能否穷举 | 能（词根 × 修饰） | 不能，必须从信息流捕获 |
| 发现工具 | 下拉、Trends、关键词库 | X、HN、GitHub、HF、sitemap |
| 搜索量 | 可估（有同类历史） | 通常为 0 或极低 |
| 窗口 | 数周–数月 | 数天–数周 |
| 适合站型 | 工具站、品类页 | 落地页、单点工具、资讯页 |

**结构性限制**：从固定词根出发，看不见「不在词根里的新名字」。这不是 bug，是边界。

**更隐蔽的问题**：`last_ratio > 6` 找的是「已经起量的词」，不是「刚出生的词」。真正的日级新词 ratio 还接近 0。所以它的「新词线」实际产出是**上升期成熟组合词**。

## 四、数据核对

- 文章标题称 122 个词根，11 步那篇称 127 个，代码块实际 **115 个**（传播失真，以可运行数字为准）
- 115 个词根里 **53 个是 `-er/-or` 工具后缀**（46%），天然偏向「AI + 工具」品类
- 与 `me/keyword-research` 的 63 个种子词只有 **22 个重合**；本地种子词是「动作/格式轴」（pdf、heic、json、base64、regex…），可作为互补

## 五、值得偷的 6 个设计

1. **统一判断链**：来源可以多，标准必须唯一
2. **社区 → Trends 回流桥**：社区只补词，不拍板
3. **大站 / niche 二分法**：简单、可解释、便宜
4. **品类均衡采样**：15 品类、每类最多 8 个、同义限 3 个，防止单词类挤爆榜单
5. **时间追踪**：连续 3 天上榜 = 信号增强；上周在、这周消失 = 短热点
6. **变现层**：CPC、SERP 付费产品、竞品质量（「有人搜」≠「有人付钱」）

## 六、不能照抄的 7 个坑

1. **「新词」定义不可操作**：没有 API 能告诉你词的出生日期，只能靠 first-seen 追踪
2. **循环验证**：Trends 既当发现器又当验证器；pytrends 非官方，429/超时是常态
3. **单一基准词 `gpts`**：基准词自身涨跌会让所有 ratio 失真；new-term-radar 也用 gpts，两者共享同一偏差
4. **词根偏差**：53/115 是工具后缀，挖不到事件词、动词性需求、非英语市场
5. **用老词量阈值筛新词**：月搜 >1000 会杀掉真正的新词（新词通常无量且数据滞后约两个月）
6. **SERP 判据太粗**：v2 里 33 个方向 26 个「值得做」（79% 通过率）；`perchance ai story generator` 首页全是 perchance.org 是**平台垄断**不是机会；KD 0 大概率是**没数据**
7. **缺供应侧信号**：没看已有多少页面专门做这个词（allintitle、sitemap 新增）

## 七、对本项目的定位

- 归入**慢线**：适合「组合型新词 / 上升期老词」，窗口周/月级，不符合「1 天上站」的主攻方向
- 可复用的是**判断链骨架**（趋势 → 社区 → SERP → 分级）和**品类均衡采样**
- 与快线（命名型新词）共享同一条判据，而不是各用一套
- 词根库可与本地 63 个种子词合并，形成「动作/格式 × AI 品类」二维矩阵
