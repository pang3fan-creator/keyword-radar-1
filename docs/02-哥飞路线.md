# 哥飞路线：供应侧侦察 + 判断工具箱

> 来源：`gitignore/gefei/` 10 篇方法论 + `Twitter-Trend-Radar/`
> 结论：哥飞体系的核心不是「找新词」，而是「找已经被验证的需求 / 正在被做的新站」。新词是副产物。它补上了孟健缺的**供应侧**。

## 一、三条线 + 一个工具箱

| 线 | 名称 | 本质 | 战场 | 窗口 |
|---|---|---|---|---|
| G1 | 漫游找词 | 需求侧：从搜索数据里找老词/组合词 | Google / Ahrefs / Similarweb | 周–月 |
| G2 | 供应侧侦察 | 从别人的站、页面、子域名、外链、排行榜反推需求 | 网站 / sitemap / 榜单 | 天–周 |
| G3 | Twitter Trend Radar | G2 的自动化切片：发布信号 → 新站线索 | X | 天 |
| G4 | 判断工具箱 | 这个词/这个站能不能打 | SERP / KD / 外链 | — |

## 二、G1 漫游找词（需求侧）

### 四栏
- **信号源**：Ahrefs / Similarweb / Semrush 关键词库、Google 下拉、相关搜索、Google Ads、Trends
- **发现机制**：任选一个起点（兴趣、品类、品牌、竞品），搜关键词 → 按 KD/量/CPC/意图筛选 → 批量导出 → 词海漫游（逐个理解用户为什么搜）
- **判断链**：KD < 30（40 也可看）、量从高到低、排除 NSFW/导航词、看 CPC、看 SERP 前 10、allintitle/kgr、域名是否已被注册
- **工程形态**：纯手工浏览，没有脚本；价值在「词感」，不在自动化

### SOP 关键数字
- 时间分配：**40% 挖需求 / 20% 开发 / 40% 推广**
- 漫游筛选：KD < 30，量降序，排除 NSFW，导航词去掉
- 二次验证：Google Ads 看准确量；SERP 看前 10 是首页还是内页；allintitle 算 kgr
- 上线前：查目标域名是否已被注册，用 AITDK 看现有站质量

### 陷阱清单（很实用）
- 导航/登录类：`class charts login` —— 不可替代
- Google 首页直接解决：`ring size chart` —— 没有点击
- 季节词：`fantasy football team names`
- 对抗性工具：`youtube to mp3`
- 品牌/公司名：`stargate ai` —— 不要做假官网，只能做专题页

## 三、G2 供应侧侦察（真正的差异化）

### 六个信号源
1. **出站链接**：v2ex、博客评论区 → 抓评论者网站 → 域名年龄 + 近三月流量 → 找偷偷赚钱的产品
2. **AI 导航站**：TAAFT、Toolify → 看新上架的工具
3. **免费托管子域名**：vercel.app、netlify.app、pages.dev、github.io 等 26 个平台 → 子域名没权重还能排上去，说明词弱
4. **大站子页面**：Gumroad Top Pages、Character.ai 自然落地页（筛「新页面」）、parade.com（经 Pinterest 流量）→ `Pick Up Lines` 单页月搜 118 万，Rizz 月入 10 万美元+
5. **排行榜/收入**：Toolify 收入榜、IndieHackers；用 Similarweb 看 `checkout.stripe.com` 的外链站估算收入
6. **线索库**：BuiltWith、GetLatka

### 逻辑
- **流量证明需求存在**（比搜索量更硬，因为已经有人拿到点击）
- **新站证明时机还在**（别人刚做，还没卷死）
- **免费托管/低权重站能排上去，证明可切入**

### 四栏
- **信号源**：站、页面、子域名、外链、榜单、Stripe 流量
- **发现机制**：反推——先看到「谁在拿流量」，再问「他靠哪个词」
- **判断链**：域名年龄、近三月流量、是否免费托管、页面类型（首页/内页）、竞品质量
- **工程形态**：手工 + 爬虫 + Similarweb/Semrush/AITDK

## 四、G3 Twitter Trend Radar（G2 的自动化切片）

### 架构
```
index.html（单文件前端）→ server.py（本地代理，零依赖）→ AISA / query.domains / aitdk
```

### 查询构造
- 33 个「发布信号词」：just launched / just shipped / introducing / built this / I made / my new tool / side project / v1 is live …
- 9 个「赛道词」：AI agent / text to video / AI image / AI voice / MCP server / background remover / resume builder / invoice generator …
- X 高级搜索：`"phrase" filter:links min_faves:N since:YYYY-MM-DD`，`queryType=Latest`
- 每次查询最多取 **25 条**，无分页

### 富化
- 灰名单约 150 个域名（大站/平台/工具/新闻/支付），命中即跳过
- 平台后缀约 50 个（vercel.app / lovable.app / hf.space …），主域名年龄无意义，改看流量
- WHOIS：query.domains 批量 JSON；.ai/.io/.app 常不公开
- 流量：aitdk 近三月月度访问
- 前端按「域名最大天龄」即时过滤；年龄未知视为合格（宁可错杀少）

### 四个具体缺陷（针对我们的目标）
1. **灰名单误杀大厂发布**：`if not cand_links: continue` 会把「OpenAI 发新模型、链接指向 openai.com」的推文整条丢掉——这恰恰是命名型新词最重要的信号源
2. **新站冷启动**：最新的站既没有 WHOIS 年龄、也没有流量数据，而代码把「年龄未知」判为合格，等于最不新鲜的线索最可信
3. **只到站，不到词**：从不抓取落地页 title/H1/meta，也不生成关键词候选
4. **不是服务端任务**：自动巡逻只在浏览器标签页开着时跑；无 cron、无持久化、无通知、英文发布词

## 五、G4 判断工具箱（可直接搬，但要降维）

| 指标 | 怎么用 | 阈值/备注 |
|---|---|---|
| 首页 vs 内页 | 前 10 全是首页 → 看整站流量；内页多 → 看该页流量 | 内页多通常意味着「词不是该站主业」，有机会 |
| KD | Ahrefs/Semrush/DataForSEO | < 30 可看；< 20 更好 |
| 外链 ROI | 流量 ÷ 引用域名数 | `aes encryption online` 前 10 需 51 个引用域名，前三约 200 个 → 不值得单独做站 |
| allintitle / kgr | 标题完全匹配页数 ÷ 月搜索量 | 文档没给阈值，需要自己标定 |
| Google Ads 量 | 最准的搜索量来源 | 会把同义词归并（ai image / ai images），要用 Trends 拆分 |
| 域名预检查 | 目标域名是否已被注册、现有站质量 | 用 AITDK 看 |
| 陷阱 | 导航、即时答案、季节、对抗性、品牌 | 见 G1 |

**关键**：这套是「域名级、长期排名」的判断。1 天上站需要的是「页面级、能否进前 10 / 有没有现成模板」的判断——KD 和外链 ROI 要降级成「SERP 前 10 是否有 3 个以上弱站/内页/无专站」。

## 六、它挖的是哪种词

| 线 | 产出 | 是否新词 |
|---|---|---|
| G1 | 成熟老词、组合词 | 基本不是 |
| G2 | 新站、新页面 | 可能是命名型，也可能是组合型，但没提取 |
| G3 | 新站线索 | 同上 |
| G4 | 判断，不产出词 | — |

**结论**：哥飞不是「新词矿工」，是「机会矿工」。要接上我们的项目，必须补一座桥：**站点 → 关键词**。

## 七、值得偷的设计

1. **供应侧反推**：流量 > 搜索量，先看谁在拿流量
2. **免费托管子域名 = 低权重试验场**：能排上去说明词弱
3. **大站子页面的「新页面」过滤**：Similarweb 的 new pages 是现成的新需求探测器
4. **外链 ROI = 流量 ÷ 引用域名**：把「能不能打」换算成成本
5. **首页/内页 + 整站/内页流量 两级判断**
6. **allintitle / kgr**：供应密度指标，便宜且少人用
7. **域名预检查 + AITDK**：避免给已注册域名做嫁衣
8. **两阶段异步 enrich**：搜索先返回，WHOIS/流量后补
9. **40/20/40 预期管理**
10. **灰名单 + 平台后缀**：工程细节，直接可复用

## 八、不能照抄的坑

1. **老词路线与 1 天上站冲突**：KD/外链/排名周期是周–月级
2. **数据源滞后、口径不一、付费**：Similarweb/Semrush/Ahrefs 三家量不一致
3. **kgr 没有阈值**；「内页多就有机会」是启发式，不是判据
4. **WHOIS 隐私/TLD 不公开**；年龄未知一律合格 → 噪声
5. **新站冷启动**：最新站既无年龄又无流量
6. **灰名单误杀大厂发布**：丢掉命名型新词的最大信号源
7. **25 条/查询、无分页、无跨天持久化、英文发布词**
8. **供应侧只到站不到词**：没有 SERP/volume 验证
9. **工具站/SEO 假设太强**：游戏、娱乐、新闻需要不同模板和信号包
10. **合规边界**：抓 Similarweb、X、sitemap 要遵守 ToS/robots

## 九、对本项目的定位

- **1 天上站**：G2/G3 做发现前端，G4 做 2 小时压缩判断，模板库做生产
- **任何流量**：不只看工具词；游戏/娱乐/新闻也进 scope，但「1 天可生产」是硬约束——新闻页最快，工具页次之，游戏页最难
- **免费优先**：免费栈日常扫描；AISA 已有；query.domains/aitdk 可选；DataForSEO SERP 做最终验证
- **多语言**：发布信号词库要本地化；灰名单/平台后缀通用
- **关键缺口**：站点 → 关键词的桥。建议用 title + H1 + meta description + related searches + autocomplete → 候选词 → 统一判断链
- **分工**：孟健 = 组合型慢线；哥飞 = 供应侧发现 + 判断；new-term-radar = 命名型快线
