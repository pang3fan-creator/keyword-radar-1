# TrendRadar：不是新词雷达，是「热榜监控 + 推送」的成熟工程

> 来源：`gitignore/TrendRadar/`（v6.11.0，GPL-3.0，约 2.9 万行）
> 结论：它不是一条「发现新词」的技术路线，而是一套成熟的**热榜监控/推送工程**。对我们的价值是三个工程件，不是主骨架；国内不作为目标市场，数据源不采用。

## 一、它是什么

- **11 个中文热榜**：今日头条、百度、华尔街见闻、澎湃、B站、财联社、凤凰、贴吧、微博、抖音、知乎（通过 NewsNow API）。
- **RSS/Atom**：可与热榜合并推送。
- **频率词过滤**：词组、必须词 `+`、过滤词 `!`、正则 `/.../`、别名 `=>`、组别名 `[组名]`、每组上限 `@N`。
- **AI 兴趣过滤**：自然语言兴趣 → 标签 → 批量打分；失败回退关键词。
- **趋势分析**：首次/最后出现时间、出现次数、排名时间线、新增标记、跨平台对比。
- **三种模式**：daily（当日汇总）/ current（当前榜单）/ incremental（增量）。
- **11 个通知渠道**：企微、飞书、钉钉、Telegram、邮件、ntfy、Bark、Slack、Webhook 等。
- **MCP 服务**：40+ 工具（最新新闻、趋势主题、日期查询、趋势分析、情感分析、相关新闻、摘要、对比时段、搜索等）。
- **时间线调度**：按星期/时段切换抓取、分析、推送、过滤方式。

## 二、四栏拆解

### 信号源
- NewsNow API 的 11 个中文热榜；RSS 订阅源。
- 不是搜索数据，不是 X/HN/PH，不是 sitemap，不是搜索量。

### 发现机制
- **Watchlist 匹配**：标题命中 `frequency_words.txt` 里的词/正则才进入报告。
- **AI 兴趣匹配**：标题按 `ai_interests.txt` 提取的标签打分，超过阈值才推送。
- **新增检测**：比较最新抓取批次与历史标题，标题首次出现即 `🆕`。
- **没有词抽取**：不会从标题里发现一个你没配置过的新词。

### 判断链
- 关键词/AI 过滤 → 按词组聚合 → 权重排序：
  - `rank_weight`（排名分，0.6）
  - `frequency_weight`（出现次数，0.3）
  - `hotness_weight`（高排名占比，0.1）
- 首次/最后时间、出现次数、排名时间线 → 判断「一次性热点」还是「持续发酵」。
- 三种模式决定「推全部 / 推当前 / 推新增」。

### 工程形态
- Python + requests + SQLite/远程存储；Docker + GitHub Actions；HTML 报告；通知分发；MCP。
- 依赖第三方 NewsNow API；可自建。
- 7 天 GitHub Actions 签到机制（试用版限制）。

## 三、三个可复用的工程件

### 1. 热榜条目的时间序列
`first_time / last_time / count / ranks / rank_timeline` 这套记忆，正是「一次性热点 vs 持续发酵」的判断基础。我们的新词雷达可以把它降维到**词级**：

```
term, first_seen, last_seen, platform_count, rank_timeline, source_count
```

它比 14 天 Trends 复盘更快，适合做「24 小时内是否值得跟进」的判断。

### 2. 多源抓取 + 域名安全 + 重试
- 每个平台配置 `expected_domain`，返回的 URL 必须 HTTPS 且域名匹配，防止 API 被劫持/投毒。
- 请求间隔 + 随机抖动 + 重试。
- 单个源失败不影响其他源。
- 这套工程细节可以直接借鉴到我们的多源采集。

### 3. 报告模式 + 通知 + 调度 + MCP
- `daily / current / incremental` 三种模式，对应「日报 / 当前榜 / 只推新增」。
- 11 个通知渠道 + 消息分片 + 各渠道格式适配。
- 按星期/时段切换过滤方式，适合「早报轻、晚报深」。
- MCP 40+ 工具，是 Agent 可用的分析界面。

## 四、关键限制：Watchlist ≠ Discovery

这是最重要的一句话：

> **TrendRadar 只能让你看到「你已经配置过的词」的热度，不能让你发现「你还不知道的词」。**

`frequency_words.txt` 是一个 10KB 的人工关注列表（胖东来、DeepSeek、华为、比亚迪、大疆、宇树、智元、黑神话、京东、字节、腾讯、特斯拉、英伟达、AMD、微软、谷歌、苹果、OpenAI、Anthropic、中国/东亚/北美/西欧、AI、芯片、航天、量子、脑机、基因……），不是词根库，也不是新词发现器。

**如果要用它做新词发现，必须把过滤层反过来：**

```
全量热榜标题 → 分词/抽词 → 与历史词表比对 → 新词候选 → 热度/持续性/跨平台 → 报告
```

这需要中文分词（jieba 等）+ 新词评分 + 历史基线，TrendRadar 本身没有。它只有「标题级新增检测」，没有「词级新词发现」。

## 五、不能照抄的坑

1. **GPL-3.0**：代码不能直接抄进闭源项目；借鉴设计可以，复制代码有许可证传染风险。TrendRadar 是 GPL-3.0，另外两个项目是 MIT。
2. **第三方 NewsNow API**：`newsnow.busiyi.world` 是外部依赖，可能限流/变更/停止；长期要自建或换源。
3. **中国中心**：默认 11 个中文平台；英文/US 新词不在这里。RSS 可以接 HN/PH，但默认没有。
4. **`!` 过滤词文档与实现不一致**：文档说「仅限当前词组」，代码里 `filter_words` 是全局列表，所有 `!` 词对所有组生效。
5. **单标签计数**：一个标题命中多个组时，`count_word_frequency` 在第一个匹配组后 `break`，只计入第一组；多标签统计需要改。
6. **没有需求验证**：没有搜索量、KD、SERP、Trends；「热」不等于「有人搜」，更不等于「能做」。
7. **标题精确匹配**：不同标题描述同一事件（「华为发布新机」vs「华为新机发布」）算两条；没有实体归一。
8. **没有多语言**：中文分词/匹配为主；英文/日文/韩文需要另做。
9. **Actions 7 天签到**：试用版机制，不适合作为长期生产调度；长期用 Docker。
10. **工程体量过大**：2.9 万行，为了「热榜推送」这个目标，很多复杂度我们用不上。
